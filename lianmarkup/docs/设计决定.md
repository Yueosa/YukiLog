# 设计决定

设计 LianMarkup 时做过的关键决定, 以及当时为什么这么想。

记下来是因为: 每个决定都有代价, 将来如果想推翻某个设计, 先来这里看看当时接住了什么、放弃了什么, 别踩回同一个坑。

---

## D1: 砍掉内嵌 HTML

**决定**: `.ly` 文件里不允许写任何 HTML 标签, 源码里的 `<div>` 一律转义为文本。

**理由**: Markdown 的内嵌 HTML 是一个逃生舱, 而逃生舱会杀死语法进化的动力 —— 想要折叠块? 写 `<details>` 就好了, 于是永远没有原生折叠块。砍掉逃生舱, 缺什么就得设计什么, 语法才会长出自己的骨头。

**代价**: 真有特殊需求时没有办法绕过。接受, 因为 YukiLog 是我自己的博客, 需求我自己控制。

## D2: 转义是三层防线的最后一层

**决定**: `\` 转义保留, 但设计上让它几乎用不到。第一层是回退规则(定界符不配对就当文本), 第二层是原样区域(行内反引号、块级 `~~~`), 第三层才是 `\`。

**理由**: 写博客是高频活动, 和 `\` 搏斗的体验太差了。`2*3=6` 不该需要任何转义。

**代价**: 回退规则让"看似语法其实是文本"的情况变多, 调试渲染结果时偶尔要想一下"它是不是被回退了"。值得。

## D3: 行首关键字后必须有空格

**决定**: `#`、 `>`、 `>>>` 等行首关键字, 后面必须紧跟 0x20 空格才生效, 否则整行是正文。

**理由**: 免费消灭一大批歧义。`#话题` 在中文写作里太常见了, 它不该是标题。这条规则写起来零成本(反正 Markdown 也要求空格), 但把"关键字和文本怎么区分"这个难题砍掉了一半。

## D4: 标题锚点用 h-N 顺序编号

**决定**: 标题自动分配 `h-1`、`h-2`..., 不用文本 slug。

**理由**: YukiLog 现有的 TOC 组件和滚动监听就是按 `h-N` 约定写的, 对齐它, 集成成本为零。

**代价**: 中间插入一个标题, 后面所有锚点都会移位, 外部深链接会失效。缓解措施是 `{#custom-id}` 显式覆盖 —— 重要的章节自己钉死锚点。

## D5: 旁注就地书写, 砍引用式脚注

**决定**: `[^备注内容]` 直接包裹内容; Markdown 的 `[^1]` + 文末定义不支持。

**理由**: "内容和定义分离"是写作时的纯负担, 改一处要动两个地方。旁注的使用场景(给某个词/某段话加说明)决定了备注就该长在它旁边。

**代价**: 和 Markdown 脚注不兼容。反正博客文章要全面重构, 不在乎。

## D6: 折叠块两种模式, 一次判定不跨界

**决定**: `>>>` 支持显式配对(`<<<` 结束)和 TAB 缩进作用域两种模式, 由下一行是否以 TAB 开头一次性判定。缩进模式里 `<<<` 永远只是文本, 显式模式里只有行首 `<<<` 是结束符。

**理由**: 写作者可以按内容形状选顺手的模式; 解析器只需要一个比特的状态, 没有模式混用的边界情况。

## D7: 解析器是 Rust crate, 放后端, 渲染期解析

**决定**: 纯函数 `parse(&str) -> Document`, 无 IO, 作为 crate 被 YukiLog 后端直接调用。不做独立 CLI/服务。文章源文存数据库, 读取时解析。

**理由**: YukiLog 的部署单元是单个 tar 包, 多一个进程就要改 systemd、备份和回滚链路。字节流、所有权、零拷贝这套思路和 Rust 是绝配, TS 的 UTF-16 字符串会跟"以 bytes 为基本单位"的设计打架。

**后手**: 将来想要编辑器实时预览, 同一个 crate 编 WASM 跑在前端, 不重写。

## D8: 产物 html/toc/notes 旁挂, 不嵌在一起

**决定**: `Document` 里 HTML 字符串和结构化元数据(TOC 树、旁注列表)分开。

**理由**: 旁注在桌面端渲染在右侧栏, 在移动端要改成"点上标展开" —— 两种前端的增强方式完全不同, 只有结构化数据分开给, 才能各自发挥。正文 HTML 本身不需要前端再解析任何东西。

## D9: KaTeX / mermaid 走"透传 + 前端增强"

**决定**: 公式输出 `<span class="lm-math">$...$</span>` 保留原始 TeX, mermaid 围栏块透传源码, 浏览器端再增强。

**理由**: RSS 阅读器里没有 JS, 退化成原始 TeX/源码依然可读; 服务端不引入 KaTeX 渲染, 解析器保持零重依赖。

**代价**: 首屏有短暂的"原始 TeX 闪现"(FOUC)。可接受。

## D10: `~~~` 是原样块, 不是代码块别名

**决定**: Markdown 里 `~~~` 和 ` ``` ` 都是代码围栏, 我们这里 `~~~` 改成"内部零解析"的原样块。

**理由**: 转义三层防线需要一个块级的原样区域, `~~~` 正好空出来了。写"介绍 LianMarkup 语法"的文档时全靠它 —— 这篇仓库的示范文章就是证明。

## D11: TOC 的位置不写进语法

**决定**: `@toc` 只声明"生成目录", 显示在左边还是右边由 CSS 决定。

**理由**: 布局是渲染层的事, 写进语法以后想改就得改语言。语法只负责结构。

## D12: 代码高亮在服务端, 不要 highlight.js

**决定**: 解析器输出 `<pre><code class="language-x">`, YukiLog 集成层用 syntect 生成内联样式。

**理由**: 服务端高亮零 JS 依赖, RSS 里也能看。(这条其实是 YukiLog 侧已有的实践, 我们顺从它。)
