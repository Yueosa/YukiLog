# LianMarkup 产物契约 (v0.1)

和 YukiLog 对齐的解析器形态与产物格式。语法本身见 [语法规范.md](./语法规范.md)

---

## 0x00 解析器形态

- **Rust crate**, 纯函数无 IO: `parse(&str) -> Document`
- **渲染期解析**: 文章源文存数据库, 读取时解析 (SSR 和公开 API 共用)
- 不做独立 CLI / 服务: YukiLog 部署单元是单个 tar 包, 不引入新进程
- 现有接缝: `server/src/markup/markdown.rs` 的 `render(&str) -> Rendered`, LianMarkup 保持同一形态
- 开发期 path 依赖隔壁仓库, 发布时再考虑 vendor 或发 crate

---

## 0x01 产物结构

HTML 字符串 + 结构化元数据旁挂, 不嵌在一起:

```json
{
  "html": "<p>…</p>",
  "toc": [{ "level": 2, "text": "…", "id": "h-3", "children": [] }],
  "notes": [{ "index": 1, "html": "…", "anchor": "note-1" }]
}
```

- `html`: 消毒后的正文片段, 前端**零解析**, 挂在 `.prose` 容器 (SSR 模板和 Lit SPA 共用)
- `toc`: 标题树, 喂给现有挂载点 (桌面端 `.post-toc` 左侧栏, 移动端 `.post-toc-mobile` 折叠块; 条目类 `.post-toc-item.level-N.is-active`)
- `notes`: 旁注列表; 桌面端渲染在右侧栏, 移动端改为"点上标展开"

---

## 0x02 锚点约定

- 标题: `h-N` 顺序编号, 支持 `{#custom-id}` 显式覆盖
- 旁注: 定义侧 `note-N`, 正文引用点形如 `<sup><a href="#note-1" id="noteref-1">1</a></sup>`

---

## 0x03 class 命名

LianMarkup 专属构造统一 `lm-` 前缀, 对齐 YukiLog 现有的单连字符小写风格:

| 构造 | 输出 |
|-|-|
| callout | `<div class="lm-callout" data-kind="question">` |
| 折叠块 | `<details class="lm-fold">` |
| 剧透 | `<span class="lm-spoiler">` |
| 注音 | `<ruby class="lm-ruby">` |
| 公式 | `<span class="lm-math">$...$</span>` (保留原始 TeX) |
| mermaid | `<pre class="lm-mermaid">` (透传源码) |
| 旁注引用点 | `<sup class="lm-noteref">` |
| 高亮 | `<mark>` |
| 行内容器 | `<span class="lm-{类名}" style="--k:v">` |
| 分栏块 | `<div class="lm-cols">` 内含 `.lm-col` × N |

## 0x04 渲染管线约束

- 代码高亮: 服务端 syntect (InspiredGitHub 主题, 内联 `<span style>`), **不引入 highlight.js** —— RSS 里也能看
- 消毒: ammonia, 已白名单 `pre`/`span` 的 `style`/`id`/`class`; 新构造的标签/属性需同步扩白名单
- LaTeX: 产物保留原始 TeX, 浏览器端 KaTeX auto-render 增强; RSS 退化为原始 TeX 文本
- mermaid: ` ```mermaid ` 围栏块透传, 前端增强; RSS 退化为源码
- diff: ` ```diff ` 围栏块透传 `language-diff`, 集成层按行首 `+`/`-`/`@@` 渲染增删视图 (绿/红/块头); RSS 退化为源码
- 图片: 输出普通 `<img>` (尺寸/分组提示放 data 属性), lightbox 由 Lit 端绑 `.prose img` 实现, 无需特殊标记

---

## 0x05 明确不做

- 独立 CLI / 服务 (多一个进程就要改 systemd、备份和回滚链路)
- 前端对正文 HTML 的任何再解析
- 正文内嵌 front matter (仅导入/迁移工具用, 存库前剥离)
